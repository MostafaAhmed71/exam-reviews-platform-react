# توثيق منصة النخبة — المراجعات النهائية

هذا الملف يشرح **المشروع كاملاً** من وجهة نظر من يستخدمه (طالب، ولي أمر، معلم إداري)، ويطلق على المنصة في الواجهة اسم **«منصة النخبة المراجعات النهائية»** لمدرسة **متوسطة وثانوية نخبة الشمال الأهلية**.

---

## 1. الهدف من المنصة

المنصة تجمع **مراجعة نهائية منظمة** حسب:

- **المرحلة**: متوسط أو ثانوي  
- **الصف**: من الصف السابع حتى الثاني عشر  
- **نوع المحتوى**: جداول اختبارات، مراجعات محلولة وغير محلولة، فيديوهات، اختبارات تدريبية إلكترونية، وإمكانيات إضافية مثل البث المجدول واستعلام رقم الجلوس  

وتربط كل ذلك بقاعدة بيانات (Supabase) مع رفع الملفات على استضافة خارجية (Hostinger عبر `upload.php` / `delete.php`).

---

## 2. ما الذي يقدّمه المشروع للمستخدم النهائي؟

### 2.1 شاشة الترحيب

- عرض شعار المدرسة وعنوان الفترة الدراسية  
- زر **«ابدأ»** للانتقال إلى التعليمات  
- دعم **السحب لليسار** على الشاشات اللمسية للانتقال التالي  
- تسجيل زيارة عند الدخول (إن وُجد جدول `visitor_tracking` في قاعدة البيانات)

### 2.2 تعليمات ولي الأمر

- نص توجيهي يوضح أن المراجعات **مرجعية** ولا تغني عن الكتاب المدرسي  
- تذكير بأن الاختبارات **وزارية مركزية**  
- طلب موافقة صريحة عبر **«قرأت التعليمات»** قبل المتابعة  

### 2.3 اختيار المرحلة والصف

- **متوسط**: الصفوف 7، 8، 9  
- **ثانوي**: الصفوف 10، 11، 12  

### 2.4 اختيار نوع المراجعة / المحتوى

من شاشة **«اختر نوع المراجعة»** يمكن للمنصة — حسب التصميم البرمجي — عرض بطاقات منها على سبيل المثال:

| النوع (في الكود) | الاسم المعروض للمستخدم | الفكرة |
|-------------------|------------------------|--------|
| `schedule` | جدول الاختبارات | صور/ملفات جداول مرفوعة لكل صف |
| `solved` | مراجعات محلولة | ملفات PDF أو عروض مع إجابات نموذجية |
| `unsolved` | مراجعات غير محلولة | تدريب بدون حل جاهز |
| `videos` | فيديوهات | فيديوهات شرح (ملفات أو روابط) مع عنوان ووصف |
| `electronic` | اختبر نفسك | اختبارات تفاعلية مبنية داخل النظام |
| `live-stream` | مراجعة ليلة الاختبار | بث/محتوى مجدول للمتوسط |
| `seat-number` | اعرف رقم جلوسك | بحث عن الطالب ورقم اللجنة والجلوس |
| `saved-videos` | الفيديوهات المحفوظة | فيديوهات احتفظ بها الطالب لمشاهدتها لاحقاً |

**ملاحظة مهمة للإصدار الحالي من الكود:** في الملف `src/pages/ReviewTypeSelection.tsx` يوجد مجموعة `temporarilyHiddenTypeIds` التي **تخفي مؤقتاً** بعض البطاقات (مثل البث والفيديو والاختبار الإلكتروني ورقم الجلوس والمحفوظات). ما يظهر فعلياً للمستخدم اليوم هو **البطاقات غير المخفية فقط**. عند الرغبة في إظهار كل الميزات، يُعدّل هذا الإعداد من نفس الملف.

## 3. مسار الطالب خطوة بخطوة (بعد اختيار النوع)

### 3.1 مراجعات محلولة أو غير محلولة

1. اختيار **المادة** من قائمة مجمّعة من قاعدة البيانات  
2. عرض ملفات المراجعة لكل مادة  
3. إمكانية **ترتيب العرض** عبر حقل `display_order` في قاعدة البيانات  
4. **تحديثات لحظية** عبر Supabase Realtime عند إضافة أو تعديل مواد تطابق نفس الصف ونوع المراجعة  

### 3.2 جدول الاختبارات

- عرض جداول مرفوعة كصور أو ملفات حسب الصف والمرحلة  

### 3.3 الفيديوهات

- قائمة فيديوهات حسب الصف؛ قد تشمل عنواناً ووصفاً ورقم واتساب للمعلم  
- إمكانية تتبع **مشاهدات الفيديو** (جدول `video_views` إن وُجد) لتجنّب عدّ مكرر لنفس الجلسة  

### 3.4 الاختبارات الإلكترونية («اختبر نفسك»)

- اختيار المادة ثم قائمة الاختبارات المتاحة  
- فتح رابط أو شاشة اختبار مرتبطة باختبار نشط في جدول `electronic_tests`  
- الطالب يمكنه أداء الاختبار؛ الإجابات تُخزَّن مع **رمز جلسة** (`session_token`) في `test_answers`  

### 3.5 الوصول بالرابط المباشر للاختبار

- يمكن مشاركة اختبار عبر عنوان يحتوي على: `#test/{share_token}`  
- يفتح **شاشة الاختبار** مباشرة دون المرور بالمسار العادي للمنصة  

### 3.6 البث و«ليلة الاختبار»

- للمرحلة المتوسطة تصميمياً: إعدادات بث في `live_stream_settings` وجدولة محتوى (صورة/فيديو) في `live_stream_schedule`  
- تتبع مشاهدات البث والمحتوى المجدول (`live_stream_views`، `live_stream_schedule_views`)  
- شاشات إعدادات للمسؤول: `LiveStreamScreen` للعرض، `LiveStreamSettingsScreen` للتحكم  

### 3.7 رقم الجلوس واللجنة

- نافذة بحث ضمن مسار المنصة: البحث بـ **رقم الهوية** مع فلترة تقريبية لنص الصف  
- لوحة `#admin-seat` أو `#admin-seat/{national_id}` لاستخدام إداري/خاص أو روابط مختصرة  

### 3.8 الفيديوهات المحفوظة

- حفظ فيديوهات من المحتوى المجدول لمشاهدتها لاحقاً (جدول `saved_videos` في سكربتات SQL المرفقة مع المشروع)

## 4. ما الذي يقدمه المشروع للإدارة والمعلمين؟

### 4.1 دخول لوحة الرفع الإدارية

- من المتصفح: إضافة `#mo` في نهاية الرابط يوجّه التطبيق إلى شاشة **Admin** (`AdminUpload`) دون المرور بتفعيل «عام» مستخدم المنصة  

### 4.2 رفع وتنظيم المحتوى (`AdminUpload`)

- اختيار مرحلة وصف و**نوع المحتوى** (جدول، محلولة، غير محلولة، فيديو، إلكتروني، …)  
- رفع ملف إلى السيرفر عبر API ثم تسجيل السجل في Supabase (`uploaded_materials`)  
- أو إدخال **رابط يدوي** للملف  
- للفيديوهات: دعم عناصر متعددة مع عناوين وأوصاف  
- حقل **واتساب المعلم** اختياري لعرضه مع المادة  

### 4.3 إدارة المواد المعروضة (`MaterialsManagement`)

- تعديل أو حذف السجلات، بما يشمل ترتيب العرض (`display_order`)  

### 4.4 إدارة المواد الدراسية كقائمة (`SubjectsManagement`)

- جداول `subjects` و`subject_grades` لتحديد المواد المرتبطة بكل مرحلة وصف  

### 4.5 الاختبارات الإلكترونية الكاملة

- `ElectronicTestsManagement` — قائمة الاختبارات  
- `TestBuilder` — بناء الاختبار ومشاركة الرمز  
- `AddQuestionScreen` — إضافة أنواع أسئلة (صح/خطأ، اختيار متعدد، مقالي، وأنواع إضافية في الأنواع البرمجية)  
- `QuestionReviewScreen` — مراجعة الأسئلة  
- `MyTestsScreen` — اختباراتي / إدارة سريعة حسب تصميم الشاشة  

### 4.6 إحصاءات (`StatisticsScreen`)

- عدد الزوار، مشاهدات الفيديو، مشاهدات البث والمجدول، وغير ذلك حسب تنفيذ `statisticsService.ts` وجداول القاعدة المتاحة  
- رسوم بيانية (Chart.js) وإطار زمني قابل للتعديل  

### 4.7 إدارة الطلاب (لجلوس اللجان)

- `StudentManagement` وخدمة `studentService.ts` تعتمد جدول `students` في Supabase  

### 4.8 شاشة بيانات اختبار خاصة

- `#tata` يفتح `TestDataScreen` (استخدام داخلي/تجريبي حسب الغرض من المشروع)

## 5. التكديس التقني (للمطور)

| الطبقة | التقنية |
|--------|---------|
| الواجهة | React 19، TypeScript، Vite |
| إدارة الحالة والتنقل داخل الصفحة | Nanostores، شاشات مفاتيح بدل React Router للتدفق الرئيسي |
| قاعدة البيانات والوقت الفعلي | Supabase (PostgreSQL، Realtime حيث يُفعّل) |
| الرفع والملفات الثابتة | PHP على استضافة (مثلاً `northelite.tech`) — مسارات محددة في `uploadService.ts` |
| أمان المحتوى في المتصفح | DOMPurify حيث يُستخدم |
| رسوم ومؤثرات | Framer Motion، Chart.js |

---

## 6. المتغيرات البيئية ذات الصلة

- بيانات الاتصال بـ Supabase عبر المتغيرات المعتادة لـ Vite (`VITE_...`) كما في `src/lib/supabase.ts` و`src/vite-env.d.ts`  
- **`VITE_SHOW_TELEGRAM_BOT=true`** لإظهار زر/عنصر عائم لربط **بوت Telegram** على الصفحة (`FloatingTelegramBot`)

## 7. مخطط قاعدة البيانات (ملخص)

| الجدول (أمثلة) | الدور |
|------------------|--------|
| `uploaded_materials` | كل الملفات والروابط المعروضة للطلاب بحسب المرحلة والصف والنوع والمادة |
| `electronic_tests` ، `test_questions` ، `test_answers` | الاختبارات التفاعلية ومشاركتها وجمع الإجابات |
| `subjects` ، `subject_grades` | قائمة المواد وربطها بالصفوف |
| `students` | بيانات الطلاب لاستعلام الجلوس |
| `visitor_tracking` | تسجيل زيارات الصفحات |
| `video_views` | تسجيل مشاهدات الفيديو |
| `live_stream_settings` ، `live_stream_schedule` | البث والمحتوى الزمني |
| `live_stream_views` ، `live_stream_schedule_views` | إحصاءات المشاهدة |
| `saved_videos` | فيديوهات محفوظة للمستخدم |

يوجد جزء كبير من الجداول في ملفات SQL منفصلة داخل مجلد `database/`؛ يُنصح بتطبيقها بالترتيب المناسب على مشروع Supabase.

## 9. الخلاصة

المشروع **منصة ويب عربية** موجهة لمدرسة محددة لتوصيل **مراجعات نهائية** و**جداول** و**وسائط تعليمية** و**اختبارات تدريبية**، مع **لوحة إدارية** لرفع المحتوى وإدارة الاختبارات والطلاب ومشاهدة **إحصاءات استخدام**. الواجهة الحالية التي يراها الزائر تعتمد على **شاشات متسلسلة** داخل تطبيق واحد، مع **روابط خاصة** للاختبار والبحث الإداري عن الجلوس، ومع إمكانية **إخبارية** لتفعيل بطاقات إضافية من خلال التعديل على إعداد الإخفاء المؤقت في شاشة اختيار نوع المراجعات.
